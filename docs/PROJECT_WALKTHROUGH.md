# 刷题系统零基础讲解

这份文档假设你完全没有代码基础。你不需要一上来理解每一行代码，你先要能讲清楚：

1. 这个网站给谁用。
2. 用户点按钮以后发生了什么。
3. 数据保存在哪里。
4. 为什么要分前端、后端、数据库、Redis。
5. 答辩老师问到时，你能用自己的话说出来。

先记一句总纲：

> 这个项目是一个考研政治刷题网站。用户在浏览器里刷题，前端负责页面，后端负责处理业务，MySQL 负责保存数据，Redis 负责保存验证码和缓存。

## 1. 先把网站想成一家餐厅

如果你完全不懂代码，可以先用餐厅理解：

| 项目里的东西 | 餐厅里的比喻 | 它负责什么 |
| --- | --- | --- |
| 浏览器 | 顾客坐的位置 | 用户看到页面、点击按钮 |
| 前端 frontend | 菜单和服务员 | 展示页面，把用户操作传给后端 |
| 后端 backend | 后厨 | 真正处理登录、刷题、统计这些业务 |
| MySQL | 账本/仓库 | 长期保存用户、题目、练习记录 |
| Redis | 临时小纸条 | 短时间保存验证码、冷却时间、缓存 |
| Nginx | 前台接待 | 上线后负责把访问分发给前端或后端 |

你答辩时可以这样说：

> 我这个系统采用前后端分离。前端像用户界面，负责展示和交互；后端像业务处理中心，负责登录校验、题库查询、答案判断和学习统计；数据库保存长期数据；Redis 保存验证码等临时数据。

## 2. 用户看到的网站，其实分成四层

从用户到数据库，路径是这样的：

```text
用户
  ↓ 点页面按钮
前端页面 Vue
  ↓ 发请求
后端接口 Spring Boot
  ↓ 查数据/存数据
MySQL / Redis
```

举例：用户点“登录”。

```text
用户输入账号密码
  ↓
前端把账号密码发给后端
  ↓
后端查数据库，判断密码对不对
  ↓
对了就返回一个登录凭证 token
  ↓
前端保存 token，之后访问页面就带着它
```

你现在先不用懂 token 的代码，只要知道：

> token 就像电影院票根。登录成功后拿到票根，之后进不同房间都要出示票根。

## 3. 这个项目每个文件夹是干什么的

项目根目录里最重要的是这几个：

```text
frontend/   前端，写用户看到的页面
backend/    后端，写系统真正的业务逻辑
deploy/     上线部署用的配置
dataset/    题库数据和导出的 Excel
docs/       给你学习和答辩用的说明文档
```

你可以先只记两个：

- `frontend`：用户看得见的页面。
- `backend`：用户看不见但真正干活的服务。

## 4. 前端是什么

前端就是你打开网站后看到的一切：

- 登录页
- 注册页
- 首页
- 专题页
- 练习页
- 模拟考试页
- 个人中心
- 后台管理页

这个项目的前端主要在：

```text
frontend/src/app/views
```

里面的文件基本就是一个页面：

```text
LoginPage.vue        登录页
RegisterPage.vue     注册页
PracticePage.vue     练习页
MockExamPage.vue     模拟考试页
ProfilePage.vue      我的/个人中心
```

你看到页面变了，通常就是这些 `.vue` 文件变了。

## 5. 后端是什么

后端是用户看不到的部分。它负责：

- 判断账号密码对不对
- 判断用户有没有登录
- 从数据库查题目
- 保存错题、收藏、练习记录
- 统计正确率和刷题数量
- 给管理员提供导入题库接口

后端主要在：

```text
backend/src/main/java/com/example/刷题
```

你先重点记这三类：

| 文件夹 | 中文意思 | 作用 |
| --- | --- | --- |
| `controller` | 控制器/接口层 | 接收前端请求 |
| `service` | 服务/业务层 | 写具体业务规则 |
| `mapper` | 数据访问层 | 和 MySQL 打交道 |

举例：

```text
StatisticsController.java
```

它就是“统计接口入口”。前端个人中心要统计数据时，会请求这里。

```text
StatisticsServiceImpl.java
```

它就是“统计业务逻辑”。比如计算过去 7 天、过去 365 天每天刷了多少题。

## 6. 数据库是什么

数据库就是系统的长期记忆。

如果没有数据库：

- 用户注册完，下次就没了。
- 题目导入完，下次就没了。
- 今天刷了多少题，下次也查不到。

这个项目用 MySQL。你可以把它理解成很多张 Excel 表。

常见表：

| 表名 | 保存什么 |
| --- | --- |
| `user` | 用户账号、昵称、密码密文 |
| `category` | 题目分类，比如马原、史纲 |
| `question` | 题目内容、选项、答案、解析 |
| `practice_record` | 每次练习记录 |
| `wrong_question` | 错题记录 |
| `favorite` | 收藏记录 |

答辩时可以说：

> MySQL 负责保存系统的核心业务数据，例如用户、题目、练习记录、错题和收藏。

## 7. Redis 是什么

Redis 也是一个存数据的地方，但它不是用来长期保存核心数据的。

你可以理解为：

- MySQL 是正式档案柜。
- Redis 是桌面便利贴。

验证码就适合放 Redis，因为验证码本来就只需要几分钟。

这个项目里 Redis 主要做：

1. 保存邮箱验证码。
2. 限制验证码不要频繁发送。
3. 缓存一些查询结果，减轻 MySQL 压力。

答辩时可以说：

> Redis 用于保存临时数据和缓存，适合验证码这种有过期时间的数据；MySQL 保存永久数据。

## 8. 用户登录到底发生了什么

先看用户视角：

```text
打开登录页
输入账号密码
点击登录
进入首页
```

系统内部其实是：

```text
LoginPage.vue
  ↓
auth.ts 调登录接口
  ↓
request.ts 发 HTTP 请求
  ↓
AuthController.java 接收请求
  ↓
UserServiceImpl.java 校验密码
  ↓
JwtUtil 生成 token
  ↓
前端保存 token
```

一句话版本：

> 登录时前端把账号密码交给后端，后端查数据库并校验密码，成功后生成 token 返回给前端，前端后续请求都带上 token。

你不需要现在背文件名，但你要知道“前端发请求、后端校验、数据库查用户、返回 token”这个顺序。

## 9. 刷题到底发生了什么

用户视角：

```text
选专题
看题目
选答案
提交
看到解析
系统记录结果
```

系统内部：

```text
PracticePage.vue
  ↓
questions.ts 调题目接口
  ↓
QuestionController.java 判断题目/答案
  ↓
statistics.ts 提交练习记录
  ↓
StatisticsController.java 保存记录
  ↓
practice_record 表新增一条数据
```

一句话版本：

> 刷题页面负责展示题目和收集答案，后端负责判断答案和保存练习记录，最后这些记录会用于个人中心统计。

## 10. 个人中心三个图怎么看

个人中心现在有三个重点：

1. 能力模型评估：雷达图。
2. 学习趋势：过去 7 天折线图。
3. 学习足迹：类似 GitHub 的一年热力图。

### 能力模型评估

它看的是五个模块正确率：

```text
马原、毛中特、史纲、思修、时政
```

后端先统计每个专题正确率，前端再把专题归到这五类，最后画成雷达图。

### 学习趋势

它看过去 7 天：

- 每天刷了多少题。
- 每天正确率多少。

两条线放在同一张图里，所以用了双 Y 轴。

### 学习足迹

它看过去一年每天有没有刷题：

- 灰色：没刷。
- 浅绿：刷得少。
- 深绿：刷得多。

答辩可以说：

> 个人中心的数据来自练习记录表，后端按日期和专题统计，前端用 ECharts 和热力图把结果可视化。

## 11. 你应该先会讲，不要先死磕代码

你现在的目标不是立刻变成程序员，而是先能把项目讲顺。

建议按这 4 层讲：

1. 用户能做什么。
2. 前端负责什么。
3. 后端负责什么。
4. 数据保存在哪里。

答辩时老师一般不会让你现场手写整个系统。他更可能问：

- 你这个系统有哪些功能？
- 前后端怎么交互？
- 登录怎么保证安全？
- 数据库有哪些表？
- Redis 有什么用？
- 个人中心统计怎么实现？
- 后续怎么部署上线？

这些问题，这份文档都能帮你回答。

## 12. 你最应该背下来的 5 句话

1. 本系统是一个前后端分离的考研政治刷题平台。
2. 前端使用 Vue，负责页面展示和用户交互。
3. 后端使用 Spring Boot，负责登录认证、题库管理、练习记录和统计分析。
4. MySQL 保存用户、题目、练习记录等核心数据，Redis 保存验证码和缓存。
5. 个人中心通过后端统计接口获取数据，再用图表展示能力模型、学习趋势和学习足迹。

如果你只能先记一点，就先记这 5 句话。

## 13. 第一轮看代码，只看这些地方

不要全项目乱看，会晕。第一轮只看：

```text
frontend/src/app/views/LoginPage.vue          登录页面长什么样
frontend/src/app/request.ts                   前端怎么发请求
frontend/src/app/router.ts                    页面怎么跳转和拦截
backend/src/main/java/.../AuthController.java 登录接口在哪
backend/src/main/java/.../StatisticsController.java 统计接口在哪
frontend/src/app/views/ProfilePage.vue        个人中心图表在哪
```

看不懂代码也没关系。你先做一件事：

打开页面，然后找到对应文件。比如你看到“个人中心”，就知道它大概率在 `ProfilePage.vue`。

## 14. 你接下来怎么学最有效

按这个顺序来：

1. 先读 `docs/DEFENSE_SCRIPT_ZERO_BASE.md`，学会把项目讲出来。
2. 再读本文件，理解每个名词。
3. 打开网站，点一遍登录、刷题、个人中心。
4. 每点一个功能，就问：“这个功能对应前端哪个页面？后端哪个接口？数据库保存了什么？”
5. 最后再开始看代码细节。

你不需要一天学会所有代码。你需要先把系统故事讲通。
