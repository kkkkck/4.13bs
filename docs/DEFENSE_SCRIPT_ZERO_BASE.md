# 毕业答辩零基础讲稿

这份是给你“直接练习怎么说”的，不是给你学代码细节的。你可以先照着读，再慢慢改成自己的话。

## 1 分钟版本

老师好，我的毕业设计是一个考研政治刷题系统。

这个系统主要面向考研学生，提供注册登录、专题刷题、模拟考试、错题收藏、学习统计和后台题库管理等功能。

技术上，我采用前后端分离架构。前端使用 Vue，负责页面展示和用户交互；后端使用 Spring Boot，负责登录认证、题目查询、答案提交、练习记录和统计分析；MySQL 用来保存用户、题库、错题、收藏和练习记录；Redis 用来保存验证码、发送冷却和缓存数据。

系统的个人中心会根据用户的练习记录生成能力模型雷达图、过去 7 天学习趋势折线图，以及类似 GitHub 的一年学习足迹热力图，帮助用户直观看到自己的学习情况。

## 3 分钟版本

老师好，我的课题是考研政治刷题系统。

我做这个系统的原因是，考研政治复习需要大量刷题和复盘，学生不仅需要做题，还需要知道自己哪个模块薄弱、最近有没有坚持练习、错题和收藏题在哪里。因此我设计了一个集刷题、模考、错题、收藏和统计分析于一体的平台。

系统分为用户端和管理端。

用户端主要包括注册登录、专题练习、模拟考试、错题本、收藏夹和个人中心。用户可以选择不同专题刷题，提交答案后查看解析，系统会保存练习记录。个人中心会根据这些记录展示累计刷题量、正确率、能力模型、学习趋势和学习足迹。

管理端主要给管理员使用，用来维护用户、分类和题库。管理员可以导入题目，管理专题分类，也可以查看系统整体数据。

技术实现上，我采用前后端分离。前端使用 Vue，页面文件主要放在 `frontend/src/app/views` 目录；后端使用 Spring Boot，接口主要放在 `controller` 目录，业务逻辑放在 `service` 目录，数据库访问放在 `mapper` 目录。

登录认证方面，我使用 JWT。用户登录成功后，后端生成 token 返回给前端，前端保存 token。之后用户访问需要登录的接口时，前端会自动把 token 放到请求头里，后端通过 JWT 过滤器解析 token，识别当前用户身份。

数据存储方面，MySQL 保存核心业务数据，比如用户、题目、练习记录、错题和收藏。Redis 主要保存临时数据，比如邮箱验证码和验证码发送冷却，这类数据有过期时间，放在 Redis 更合适。

统计功能方面，后端根据 `practice_record` 练习记录表做聚合统计。比如个人中心的雷达图来自各专题正确率，折线图来自过去 7 天每天刷题数量和正确率，热力图来自过去一年每天的刷题数量。前端拿到这些数据后，用图表展示出来。

部署方面，项目支持后续用云服务器部署。上线时可以用 Nginx 托管前端静态文件，Spring Boot 提供后端接口，MySQL 和 Redis 在服务器内部运行，公网只开放 80 和 443 端口。

## 老师问：你这个项目是干什么的？

可以回答：

> 这是一个考研政治刷题系统，主要帮助学生按专题刷题、模拟考试、整理错题收藏，并通过学习统计图表查看自己的薄弱模块和学习趋势。

## 老师问：为什么要做这个系统？

可以回答：

> 考研政治复习需要大量重复练习。如果只做纸质题，很难统计正确率、错题和学习趋势。所以我做了这个系统，让用户不仅能刷题，还能看到自己的学习数据。

## 老师问：前端和后端分别做什么？

可以回答：

> 前端负责用户看得见的页面，比如登录页、刷题页、个人中心。后端负责真正的业务处理，比如校验登录、查询题目、保存练习记录、统计正确率。

## 老师问：数据库保存了什么？

可以回答：

> 数据库保存核心业务数据，包括用户表、题目表、分类表、练习记录表、错题表和收藏表。用户每次刷题后，系统会把本次练习记录保存到数据库，后续统计图就是根据这些记录计算的。

## 老师问：Redis 是干什么的？

可以回答：

> Redis 主要保存临时数据，比如邮箱验证码和验证码发送冷却。验证码只需要短时间有效，所以不适合长期放在 MySQL，放在 Redis 更简单，也方便设置过期时间。

## 老师问：登录怎么实现？

可以回答：

> 用户输入账号密码后，前端把信息发给后端。后端查询数据库并校验密码，校验成功后生成 JWT token 返回给前端。之后前端每次请求都会带上 token，后端解析 token 来确认用户身份。

## 老师问：密码安全吗？

可以回答：

> 密码不是明文保存的。注册时后端会使用 BCrypt 对密码加密后再存入数据库。登录时也不是解密密码，而是用 BCrypt 的匹配方法比较用户输入和数据库里的密文。

## 老师问：个人中心的雷达图怎么实现？

可以回答：

> 后端先统计每个专题的正确率，前端再把专题归类到马原、毛中特、史纲、思修、时政五个维度，最后用 ECharts 的雷达图展示出来。

## 老师问：学习趋势怎么实现？

可以回答：

> 后端按日期统计每天刷题数量和正确率，并补齐没有刷题的日期。前端拿到过去 7 天的数据后，用双 Y 轴折线图展示刷题数量和正确率。

## 老师问：热力图怎么实现？

可以回答：

> 热力图使用过去一年每天的刷题数量。后端返回连续日期数据，前端按周排列成 7 行多列的小方块，颜色越深表示当天刷题越多，效果类似 GitHub 的贡献图。

## 老师问：你项目最大的难点是什么？

可以回答：

> 我认为难点主要有三个。第一是前后端登录状态的衔接，需要让 token 在前端保存，并在后端正确解析。第二是题库和练习记录的数据关系，需要保证用户刷题后能正确保存记录。第三是个人中心统计图，需要把数据库里的记录转换成用户能看懂的图表。

## 老师问：后续怎么改进？

可以回答：

> 后续可以继续优化三方面。第一是推荐系统，根据错题和薄弱模块推荐题目。第二是部署上线，用云服务器、Nginx、MySQL 和 Redis 搭建正式环境。第三是增加更多测试和数据备份，提升系统稳定性。
